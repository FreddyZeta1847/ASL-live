ASL·live

An offline sign-to-speech device for a mute user.

A mute user fingerspells ASL letters into a USB camera. The Pi recognizes them, builds a word, translates it into the user’s chosen language (IT · ES · FR · EN · DE), and speaks it through a USB speaker. No phone. No cloud. No internet.

Python 3.11+ MediaPipe PyTorch → ONNX Argos Translate Piper TTS Raspberry Pi 5
What it does

Fingerspell a word. Hear it in your language.

A single Python application runs three workers in parallel on the Pi: a recognizer that turns camera frames into letters, a translator that converts each finished word from English to the target language, and a speaker that synthesizes audio. Two buttons and a 16×2 LCD give the user full control without a phone or screen.

See

USB webcam → 21 hand keypoints

MediaPipe Hands extracts 21 (x, y, z) keypoints per frame at ~30 fps on the Pi 5.

Think

Tiny MLP → one of 26 classes

A 4-layer MLP classifies the 63-dim landmark vector into 24 letters + SPACE + DELETE.

Speak

Argos translate → Piper TTS

Each finished word is translated and spoken in the chosen language — entirely on-device.

Section 03 · The centerpiece

Recognition AI — six decisions that define the model.

Most of the engineering thought in ASL-live lives here: the choice of input representation, the model size, how training is shaped to avoid failure modes, and how raw per-frame predictions become committed letters.

3.1 Landmarks, not raw pixels.

The single most important architectural call. Instead of training a CNN on camera images, we let MediaPipe extract 21 hand keypoints first and classify those.

Rejected

CNN on raw 224×224 images

  • Tens of thousands of labeled image samples per class
  • Tens of MB model, slow to train and ship
  • Fragile to lighting, skin tone, background, framing
  • GPU strongly preferred for training
vs
Chosen

MLP on 63 normalized landmark floats

  • ~3 k samples per class enough; trains in minutes on CPU
  • ~120 KB model; deployable as a single ONNX file
  • MediaPipe handles invariance to lighting and background
  • Inference under 5 µs per frame on the Pi

3.2 The 63-dim feature vector.

Each frame becomes 21 keypoints × 3 coords = 63 floats. Two normalization steps make the model translation- and scale-invariant.

1

Translate to wrist origin

Subtract landmark 0 from all 21 points. The hand’s absolute position in the frame stops mattering.

2

Scale to unit max-distance

Divide by the largest distance from the wrist. A close-up hand and a far hand now produce the same vector.

3

Flatten to 63 floats

(21, 3) → (63,). This is the exact input the MLP sees — no images, no convolutions, just numbers.

3.3 A four-layer MLP. Nothing fancier.

Right tool for low-dimensional tabular classification. CNNs need spatial input; RNNs / Transformers need sequences. We have neither — just 63 abstract numbers per frame.

~30 k parameters
~120 KB on disk (FP32)
< 5 µs per inference
26 output classes

XGBoost is trained alongside as a baseline sanity check — if it beats the MLP by >1% macro-F1, the MLP is misdesigned. It is not deployed.

3.4 Training recipe — balanced for the failure modes we expect.

Imbalanced data and small custom classes (SPACE, DELETE) are the two big risks. The recipe is tuned to address both.

Dataset

Public + custom mix

~3 k samples per letter from a public Kaggle set; ~500 each for SPACE and DELETE from custom webcam capture. Mirror-flipped at ingest for free 2× data.

Loss

Class-weighted cross-entropy

Weights inversely proportional to class frequency. A SPACE mistake costs the optimizer ~6× more than a letter mistake — otherwise SPACE accuracy gets sacrificed.

Augmentation

Noise · scale · translate

Each sample gets independent 50% chance of Gaussian noise (σ=0.01), uniform scale [0.95, 1.05], xy translation ±0.02. No rotation, no flip (flip already happened).

Split

80 / 10 / 10 stratified, seed 42

Stratified preserves class proportions. Val drives early stopping and LR schedule; test is touched exactly once at the end.

Optimizer

Adam · lr 1e-3 · wd 1e-4

Adam’s per-weight adaptive learning rate plus momentum — works on the first try for ~95% of small projects.

Stopping

Early stop, patience 10

Halt when val loss has not improved for 10 epochs; keep best checkpoint. ReduceLROnPlateau halves LR after 5 stagnant epochs.

Acceptance bar (both must hold)

Macro-F1 ≥ 0.95 on test set ·  no off-diagonal confusion-matrix cell exceeds 2% of its row total. If either fails, do not advance — collect more data for the weak class, swap a confusing gesture, or adjust the model.

3.5 Per-frame predictions → committed letters.

The MLP fires 30 times a second. Without debounce, holding one sign for a second would produce 30 of the same letter. A two-state machine with a stability counter and a cooldown gap turns the prediction stream into exactly one commit per intentional sign.

Knobs: STABLE_FRAMES = 5, MIN_CONF = 0.85, GAP_FRAMES = 3. Re-tuned in phase 7 from real-use logs.

3.6 Trained in PyTorch, deployed as ONNX.

ONNX is a file format, not a model — like JPEG for images. The trained MLP could equally be saved as .pt or .tflite; we pick .onnx because the runtime is a single ~50 MB Python package with no other dependencies. PyTorch never gets installed on the Pi.

Why ONNX, not TFLite

TFLite is tuned for mobile and accelerator hardware (Coral, NPUs) — irrelevant on a plain Pi 5 CPU. ONNX has the better Python ecosystem, numpy interop, and debug tooling.

Quantization — skipped for v1

FP32 → INT8 would save 90 KB and a few microseconds. The Pi 5 has 8 GB of RAM. Revisit only if profiling demands it (it won’t — MediaPipe dominates the frame budget).

Section 04

26 classes — 24 letters + 2 control gestures.

J and Z are skipped because they require motion; the alphabet-fingerspelling alphabet uses only static handshapes. Two control gestures replace the keyboard buttons a phone keyboard would have: an open palm commits the word, a thumb-side fist deletes the last letter.

letter skipped (motion) control gesture
SPACE

Open palm, five fingers spread

Commit the current word: send it to the translator, speak it, and clear the buffer. Visually distinct from every letter shape.

DELETE

Closed fist, thumb extended sideways

Remove the last letter from the buffer. Reads as a backspace arrow (←); thumb-side over thumb-down because the wrist rotation is easier when holding the device in the off hand.
